# Simplified Technical English (ASD-STE100) mode

Use for text a reader must follow exactly, with no one to ask: procedures, error messages, tool
descriptions, system prompts, subagent briefs, runbooks. Not for chat, persuasion or creative copy.
Sources and the official dictionary: `ste100-sources.md`. Worked examples:
`../examples/ste100-before-after.md`.

This is STE-inspired, not certified STE. The structural rules below are checkable. The word-level
rules need the official ~900-word dictionary, which is not reproduced here, so treat them as "prefer
plain words" and never claim dictionary compliance.

## Structural rules (apply)

| Rule | Do | Don't |
|---|---|---|
| Active voice | "The agent deletes the file." | "The file is deleted." (unless the actor is unknown) |
| No phrasal verbs | "Remove the panel." "Start the job." | "Take off", "spin up", "reach out", "dive into" |
| One instruction per sentence | "Open the file. Read line 3." | "Open the file and read line 3, then check..." |
| Sentence length | 20 words or fewer for instructions, 25 for descriptions | Long chains of clauses |
| No semicolons | Two sentences | Any semicolon |
| Short noun clusters | 3 words or fewer ("fuel pump valve") | "high pressure fuel pump inlet valve assembly" |
| No dropped words | Keep subject, verb and article | "Files not backed up will be lost" |
| Keep modality | "may have failed" stays "may have failed" | Turning a hedge into a fact |
| One topic per paragraph | 6 sentences or fewer | Mixed topics |
| Lists for sequences | Numbered list for 3 or more steps | A sequence buried in one sentence |
| Simple tenses | "We received the report." | "We have received the report." Keep a compound tense only when it carries meaning ("has completed and is available now", "may have failed") |

## Word habits (prefer, do not enforce)

- One word, one meaning: pick "check" and never rotate to "verify" and "confirm" for the same act.
- Verb, not noun: "analyze the log", not "perform an analysis of the log".
- Define a necessary domain term once.

## Procedure

1. Read the whole text for meaning first.
2. Run the linter: `python3 ~/.skills-library/skills/writing/scripts/ste-lint.py --max-words 20 FILE`
   for instructions (the default 25 is for descriptions; stdin works; `--json`, `--baseline N`,
   `--disable rule1,rule2`). It checks semicolons, sentence length, phrasal
   verbs, nominalization, marketing adjectives, synonym rotation, dangling conjunctions in lists,
   passive voice and compound tenses. Keep real uncertainty ("may have failed" stays). Review tense findings by hand.
3. Before enforcing length, list the conditions, sequence, units, negations and modality in the
   original. Rewrite each flagged sentence without changing its meaning. Never upgrade a hedge, never add a
   cause, frequency or mechanism the source did not state. If a rewrite would drop a safety
   condition, scope qualifier or number, keep the longer phrasing.
4. Output only the rewritten text. Add one line `Kept as-is: <phrase> (<precision kept>)` only when
   step 3 kept a longer phrasing. Show a rule table only when asked.
5. Re-lint the rewrite with the same `--max-words` and `--baseline 0` and compare the conditions, units, negations and
   modality list with the original. List only the exact exceptions needed to keep the meaning.
6. If the text already complies, say so and change nothing.

STE fixes form, not substance. A hollow paragraph stays hollow. Stop when the sentence is
unambiguous, not when it is shortest.
